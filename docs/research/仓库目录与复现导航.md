# 仓库目录与复现导航

更新于 2026-11-07，面向首次接手的合作同学。路径均相对于仓库根目录。

## 先读哪几份文件

1. 阅读本文，确认代码、数据、实验和结果的关系。
2. 阅读 [实验索引](../../experiment-log/README.md)，找到正在讨论的实验编号。
3. 阅读该轮 `GOAL_PROMPT.txt` 或 `plan.md`，再看 `RESULTS.txt` 或 `results.md`。
4. 核对 `protocol.json`、`preflight.json`、`freeze.json`、`decision.json` 和逐种子 CSV。
5. 需要运行时，按 [复现入口](../../experiment-log/REPRODUCING.md)准备环境及外部产物。

当前可以先看 [05 弱分量覆盖结果](../../experiment-log/2026-11-06-05-weak-component-goal/RESULTS.txt)及 [阶段复盘与下一步](2026-11-07_阶段复盘与协作计划.md)。

```text

├── projects/                 两套 Python 研究工程
│   ├── CJ_Imbalance_0716/     Route A，六标签识别与长尾研究
│   └── CJ_Inbalance_0724/    Route B，识别与物理参数等多任务研究
├── data_generation/          MATLAB 物理信号生成器及配额规划
```

## 第三层，数据生成器与数据索引

`data_generation/0716/` 与 `data_generation/paper/` 都保留原工程下的可配置生成、长尾组合生成、组合生成、`Jam9` 和说明目录。具体入口以各轮脚本中的 `generatorRoot` 为准。

当前实验使用 `data_generation/0716/可配置组合干扰数据生成/`。

| 子目录或文件 | 职责 |
|---|---|
| `core/` | 参考信号、组合 manifest、配置验证与生成流程 |
| `generators/` | 各干扰分量的物理波形生成 |
| 同层配置及入口脚本 | 组织参数、启用标签和生成数据 |

实验目录内的 `generate_*.m` 调用上述生成器，并冻结本轮标签、身份种子、候选池规模和输出角色。

`data/catalog/` 按版本建目录。

| 版本目录 | 阅读重点 |
|---|---|
| `closedset_6class/` | 基础闭集数据契约 |

| `six_class_pure_label_longtail_v1_IF3_CF8_N8000/` | v1 长尾构造和原始标签约定 |

旧六类包含 VFT。当前六类顺序为 `[FMB, AMA, SawFM, SinFM, MFT, ISRJ]`。读数据时以对应版本契约为准。11 月各轮重新生成的数据身份及划分记录在该轮 manifest 中。[数据版本说明](数据集版本与使用说明.md)

### 一个实验目录内部怎样分层

```text
某轮实验/
├── GOAL_PROMPT.txt 或 plan.md      研究目标、预算与评价规则
├── run_*.py                      训练或诊断入口
├── generate_*.m / prepare_*.py    生成、身份审计与角色划分
├── analyze_*.py / summarize_*.py  统计、绘图和报告
├── RESULTS.txt 或 results.md     人可读结果及限制
└── results/ 或 screen_results/   可复核的轻量运行产物
    ├── protocol.json             本轮协议
    ├── preflight.json            输入、环境、代码和权重验收
    ├── freeze.json               评价前冻结的模型和校准参数
    ├── decision.json             差值、门槛与晋级决定
    ├── evaluation_*.csv          总体、逐标签、逐组合指标
    ├── paired_*.csv              同身份功率响应
    ├── verification*.json        验证收据
    ├── artifact_sha256.json      原始运行产物哈希
    └── W_2060/ 等                方法组加训练种子
        ├── history.json          逐轮训练和选模指标
        ├── receipt.json          该运行的设置、身份和产物记录
        └── calibration.json      校准参数
```

各轮按实际产物保留文件，01 的文件命名与上述通用结构略有区别。`A/B/C/D/W` 的含义必须查本轮协议，例如 01 的 B 表示组合覆盖，05 的 B 表示余弦学习率。`2060` 等表示训练种子，五种子汇总计算的是五个独立模型的指标均值。

## 第五层，运行时外部目录中的角色

| 角色 | 数量 | 用途 |
|---|---:|---|
| fit 候选池 | 25,200 | 从中按冻结配额选择训练身份 |
| 实际 fit | 8,000 | 参与梯度更新，每轮全部遍历 |
| early_stop | 1,008 | 选择检查点 |
| calibration | 1,008 | 拟合阈值和温度 |
| development / confirmation | 4,032 | 按该轮协议统一评价 |

05 的 manifest 沿用字段名 `development`，科学角色是该轮新身份 confirmation。读取角色需要同时查看协议。05 这批确认身份已经被评价消费。

外部完整运行目录还包含 MAT、checkpoint、冻结 logits 和恢复状态。仓库结果目录中的 `artifact_sha256.json` 可能引用这些外部文件。原始运行路径留作来源记录，复现应通过参数传入本机路径。

## 师弟接手时的顺序

1. 拉取仓库后先运行两个哈希校验命令，确认交付完整。
2. 根据研究问题选择一轮实验，先看协议与结果，再读入口脚本。
3. 对齐 AMA 六类标签、8000 身份配额、功率范围、数据角色及初始权重哈希。
4. 配置本机外部数据位置，先运行 CLI 帮助和输入验收。
5. 新实验建立新目录和新输出版本，保存配置、实际代码哈希、模型种子和身份记录。
6. 结果回填包括逐种子差值、逐类代价、失败与停止原因，更新实验索引。

你提供的分段读出总结归档于 [协作材料](collaboration/README.md)。目前两边的绝对 Exact 使用各自数据池，联合实验需要统一身份和预算后再比较。
